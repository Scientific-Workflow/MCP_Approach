# Clarifier + Per-Run Output Archiving

Branch: `master_feat/clarifier`

This note documents two changes on this branch so a teammate can pick the work up
and run the remaining papers (cosmology / eddy) on HPC without reverse-engineering
the diff:

1. **Clarifier** — an *optional* agent node that the orchestrator calls when a
   request is underspecified, asking the user **only the missing details**.
2. **Per-run output archiving** — every run's outputs (figures, data, trace) are
   copied into their own self-describing folder outside the repo, instead of
   piling up / overwriting each other in the shared `work/run0` scratch directory.

Plus one small infra fix (`streaming=True`) needed for long runs against the Argo
LLM endpoint.

---

## 1. Clarifier (optional, orchestrator-routed)

### What it does
When a user gives a **partial** request (e.g. *"a 2-task producer/consumer workflow
that simulates crystallization and then visualizes the results"*), the orchestrator
now judges that key details are missing and routes to a **clarifier** node. The
clarifier:

- Inspects the prompt and figures out which of the **6 spec slots** are already
  covered.
- Asks the user **only the missing slots** (not all six).
- For any slot the user still leaves blank, an LLM fills in a single reasonable
  assumption.
- Produces a **clarified spec** that the planner then consumes.

Every slot records its **provenance**:
`[prompt]` (already in the request) · `[user]` (answered a clarifying question) ·
`[agent]` (assumed by the LLM). This keeps the whole thing traceable for evaluation.

### The 6 slots
| key | question |
|-----|----------|
| `scientific_goal` | what should the workflow compute or produce? |
| `software` | which simulator and analysis tools should each task use? |
| `input_data` | provided, or generated by the workflow itself? |
| `parameters` | size, steps, resolution, MPI ranks (blank = defaults) |
| `outputs_success` | what outputs, and how do we know it worked? |
| `environment` | local or HPC, how many processes / ranks / nodes? |

### How it's wired into the graph
The clarifier is a **supervisor-pattern** node — the orchestrator decides when to
use it, and control returns to the orchestrator afterward:

```
user gives a PARTIAL prompt
        │
        ▼
   orchestrator ──(request underspecified & not yet clarified)──► clarifier
        ▲                                                            │
        │  clarified: yes  ◄─────────────(clarified spec)────────────┘
        ▼
   planner ─► installer ─► explorer ─► end
```

A **loop-guard** ensures the clarifier runs at most once: once `clarified` is true,
the orchestrator will not route back to it (it forces `planner` instead).

### Files touched
- **`clarifier.py`** *(new)* — self-contained, UI-agnostic module. Exposes
  `run_clarifier(seed_prompt, answer_fn, fill_fn, detect_fn)`. The pluggable
  functions let the same logic drive a real CLI user, a notebook, or a *simulated
  user* for batch evaluation (`make_simulated_user_answer_fn`). Imports only `json`
  + `langchain_openai` (lazily); it does **not** depend on the agent graph.
- **`agent_mcp.py`**:
  - `OrchestratorOutput.next` gained the `"clarifier"` option.
  - `ORCHESTRATOR_SYSTEM_PROMPT` (both the full and the no-skills variant) now
    instructs the LLM when to route to the clarifier and to do so at most once.
  - `AgentState` gained `combination`, `clarified_spec`, `clarified`.
  - The orchestrator now sees the clarified status + spec in its context, and has a
    hard-override loop-guard.
  - New `clarifier_node()` function; the graph gains the node, a conditional edge
    from the orchestrator, and an edge back to the orchestrator.
  - The planner consumes `clarified_spec` when present.
  - The **old** behaviour (clarifier hard-coded as a pre-processing step in
    `__main__` for combination `d`) was removed — it is now fully graph-driven.

### How to exercise it
Give a deliberately **underspecified** `--goal` (combination `d` = description only):

```bash
python3 agent_mcp.py --combination d --domain molecular \
  --goal "I want a 2-task producer/consumer workflow that simulates crystallization and then visualizes the results."
```

The clarifier reads answers from **stdin**, so run it in an interactive terminal.
Answer what you know; press **Enter** on a blank line to let the agent assume that
slot. A **full**, detailed prompt will typically skip the clarifier entirely — that
is expected; it is optional by design.

## 2. Per-run output archiving

### The problem
`work/run0` is a single fixed scratch directory shared by **every** run (hard-coded
as `DEFAULT_WORK_DIR` in `servers/parsl_server.py` and `servers/pycompss_server.py`,
and referenced in skill text as `/app/work/run0`). Each run overwrites / mixes with
the previous run's files, so it was impossible to tell which figures came from which
run.

### The fix (`run_archiver.py`)
At the end of **every** run (both success and failure paths in `agent_mcp.py`),
`archive_run()` copies that run's outputs into a clean, self-describing folder:

```
<ARCHIVE_ROOT>/<name>_<MMDD>_<HHMMSS>/
├── trace.json
└── work/            # only THIS run's files (filtered by mtime >= run start)
    ├── renders/     # e.g. frame_0000..frame_0089.png, animation.gif
    ├── frames/      # simulation trajectory output
    └── ...
```

- **Folder name** = `<name>_<MMDD>_<HHMMSS>`, where `name` is the paper's file name
  (combinations a/b/c) or the `--domain` (combination `d`, no paper).
  Example: `molecular_0721_105840`, `cosmology_0722_143012`.
- **Only this run's files** are copied — an `mtime >= run-start` filter skips stale
  output left behind by earlier runs in the shared `work/run0`.
- `work/run0` itself is **not** touched, since servers and skills hard-code it.

### Where the archive goes (`ARCHIVE_ROOT` resolution)
Resolved in this order:
1. **`MCP_ARCHIVE_ROOT`** env var, if set (explicit override).
2. The **LCRC/HPC** path `/gpfs/fs1/home/jacob.oh/SULI/TEST_RUNS/mcp_approach`,
   if its parent exists (i.e. you're on HPC).
3. **`~/MCP_runs`** as a local fallback — so a laptop run always archives somewhere
   instead of silently dropping the output.

So on HPC it archives to the gpfs path automatically; on a laptop it archives to the
home directory automatically. No env var needed in either case (but you can override).

### Where to find the folder
| Platform | Path |
|----------|------|
| macOS | `/Users/<user>/MCP_runs/` (`~/MCP_runs`) |
| Windows | `C:\Users\<user>\MCP_runs\` (`%USERPROFILE%\MCP_runs`) |
| HPC (LCRC) | `/gpfs/fs1/home/jacob.oh/SULI/TEST_RUNS/mcp_approach/` |

## 3. Infra fix: `streaming=True`

The Argo LLM endpoint rejects non-streaming requests that may run longer than
10 minutes with a `500 - Streaming is required...` error. `streaming=True` was added
to the `ChatOpenAI` client (this branch's diff includes the explorer's coder-model
client in `mcp_explorer.py`). Without it, long runs fail mid-way.

## 4. Running the remaining papers on HPC

The other two use cases are HPC-only (the explorer's `get_resources` guard stops a
run that isn't inside a PBS allocation):

- **cosmology** (HACC)
- **eddy** (Nek5000)

Run inside an LCRC PBS allocation. The archive root is auto-detected on HPC, so
`MCP_ARCHIVE_ROOT` is optional there.

```bash
# Full prompt + paper (clarifier will typically be skipped):
python3 agent_mcp.py --combination b --engine parsl --env hpc \
  --domain cosmology --paper <path/to/cosmology.pdf> \
  --goal "<full task description>"

# Partial prompt (to exercise the clarifier), description-only:
python3 agent_mcp.py --combination d --engine parsl --env hpc \
  --domain eddy \
  --goal "<short, underspecified description>"
```

### CLI reference
| flag | values | meaning |
|------|--------|---------|
| `--combination` | `a` \| `b` \| `c` \| `d` | `a`=PDF+Image+Desc, `b`=PDF+Desc, `c`=Image+Desc, `d`=Desc only (**required**) |
| `--engine` | `parsl` \| `pycompss` \| `adios` | workflow engine (default `parsl`) |
| `--env` | `local` \| `hpc` | execution environment (default `local`) |
| `--condition` | `A` \| `B` \| `C` | ablation: A=no-skills, B=full (default), C=single-agent |
| `--domain` | free text | use-case label, e.g. `cosmology`, `eddy`, `molecular` |
| `--paper` | path or 1-based index | PDF paper (combinations a/b) |
| `--image` | path | figure/diagram (combinations a/c) |
| `--trial` | int | trial number for repeated runs (default 1) |

After each run, look in `<ARCHIVE_ROOT>/<name>_<MMDD>_<HHMMSS>/` for that run's
figures, data, and `trace.json`.
